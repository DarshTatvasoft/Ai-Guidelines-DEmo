Same or separate agents for testing and code review  Testing and code review can use the same agent and model as development, or a separate agent and model, as  applicable.  NORM A L AN D C OM P LEX C HA NGE S  For normal and complex changes, prefer   a separate agent  with a fresh context , because an agent checking its own  work tends to confirm it rather than question it.  SIM P LE C H AN GES  For very simple   straightforward   changes, the   same  development agent may work for   quick   test and  review.  •   Testing   checks behaviour, negative cases, edge cases, and coverage.  •   Code review   checks correctness, architecture, security, performance, and maintainability.  •   Critical changes   get a stronger model and mandatory human approval.

Copy/paste prompt examples  Type   Prompt  Simple   Add a required - email validation to the existing Customer DTO and update the related unit test.  Follow the existing project pattern.  Normal   Add CSV customer import using the existing API/service pattern. First inspect the existing  Customer and import code, and create a plan. Do not modify code until the plan is clear. Code review   Review only the current changes. Do not modify files. Check correctness, security, performance,  project conventions, and test coverage. Return findings grouped as Critical / Warning /  Suggestion.  7. Cost and safety rules  •   Select the lowest suitable model   explicitly . Avoid Auto; it can move to a higher - cost model without your  consent.  •   Reserve stronger models for complexity or risk;   do not   move every task to the highest tier.  •   Use   scripts or automation   for repetitive, deterministic work instead of asking an AI model repeatedly.  •   Use the same or a separate agent and model for testing and code review, as applicable; prefer a separate  agent for normal and complex changes.  •   Never   put secrets, production credentials, or restricted data into an AI tool unless the Company/Client has  explicitly approved that environment.  •   Human review is   mandatory   for security, authentication/authorization, production data, infrastructure, and  other high - impact changes.
