K E Y T AK E AW A Y  Model Context Protocol (MCP)   is a standard way for AI applications to connect with external tools, systems  and data sources. Instead of keeping the AI editor isolated from the tools developers use every day, MCP  allows the editor to interact with   approved systems   through an   MCP server .  For example, an AI editor can use a   Figma MCP server   to understand a design and help generate code based on  it, or use a   Jira MCP server   to read project issues and update information when the required permissions are  available.  A typical flow looks like this:  Developer   ➜   AI Editor   ➜   MCP Server   ➜   External Tool  The AI editor sends a request to the MCP server, and the MCP server performs the   permitted operation   against the  connected system.  MCP is useful because developers can work with external systems   without repeatedly switching   between the AI  editor and other applications. It can also give the AI   more relevant project context   and allow repetitive tasks to  be handled through   natural - language instructions .  Benefits of MCP for Developers  ✔   Access information from external tools directly  from the AI editor.  ✔   Reduce context switching between the code editor  and tools such as Figma, Jira or documentation  systems.  ✔   Give the AI better context by allowing it to retrieve  relevant project information.  ✔   Automate repetitive tasks that would otherwise  require manual navigation.  ✔   Use natural - language instructions for supported  operations instead of manually performing every  step.  ✔   Keep development work connected with the  actual project information and design  requirements.  ✔   Create opportunities to connect AI editors with  internal tools and approved company systems.  ✔   Improve developer productivity when the MCP  integration is configured with appropriate  permissions and clear usage guidelines.

The   permissions granted to the MCP connection  therefore matter as much as the MCP integration itself.  P R I NC I P L E O F L E AS T P R I VI L E G E  Developers should follow the   principle of least privilege : provide only the access that is actually required  for the task.  #   Guideline  1   Use the minimum permissions required for the MCP connection.   If the developer only needs to retrieve  information, use a Figma/Jira account or authentication token with read - only access. Avoid granting edit,  delete, or administrative permissions unless they are specifically required.  2   Restrict unnecessary MCP tools in the AI editor.   If the connected Figma/Jira account already has edit or  delete permissions, remove or disable the corresponding destructive tools from the AI editor/MCP  configuration where supported. For example, if Jira   delete_issue   is not required, it should not be made  available to the developer through the AI editor.  3   Use separate development/test credentials   where practical instead of connecting an AI tool directly to  sensitive production accounts.  4   Never   place API keys, access tokens or passwords directly in source code or commit them to Git.  5   Do not   paste sensitive credentials into AI prompts or chat conversations.  6   Understand what data the MCP server can access   before connecting it to an account.  7   Use MCP servers from trusted and approved sources.   Avoid installing unknown MCP servers simply  because they appear useful.  8   Review the permissions   of an MCP integration when it is installed or updated.  9   Disable or remove   MCP connections that are no longer required.  10   Before allowing a write operation,   make sure the AI is acting on the correct project, file, issue or  environment.  11   For destructive or high - impact operations,   review the intended action   before allowing it to execute.  R E C O M M E N D E D AP P R O AC H  Start with the   minimum required permissions . Increase access only when there is a clear business or  development need.
